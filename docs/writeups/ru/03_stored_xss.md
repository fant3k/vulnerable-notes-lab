# 03. Stored XSS в заметке

## Суть

Приложение сохраняет body заметки как есть и затем вставляет его в HTML без escaping. Если пользователь сохранит `<script>`, браузер выполнит его при открытии заметки.

## Как воспроизвести

1. Войдите в приложение.
2. Создайте новую заметку с body:

```html
<script>alert(document.cookie)</script>
```

3. Откройте созданную заметку.
4. Браузер выполнит JavaScript.

## Где проблема в коде

В `vuln_notes/templates.py`:

```python
<div class="note-body">{note['body']}</div>
```

`note['body']` намеренно не проходит через `html.escape()`.

## Impact

Stored XSS опаснее reflected XSS: payload сохраняется в базе и срабатывает у каждого пользователя, который открывает зараженную заметку. В реальном приложении это может привести к краже session tokens, действиям от имени пользователя или подмене интерфейса.

## Как исправить

Минимально:

```python
escape(str(note["body"]))
```

Если приложению нужен Markdown/HTML, нужно использовать allowlist sanitizer, например Bleach, и разрешать только безопасные теги и атрибуты.

Также стоит добавить CSP, но CSP не заменяет output encoding.

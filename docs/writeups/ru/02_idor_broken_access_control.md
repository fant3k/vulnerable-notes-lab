# 02. IDOR / Broken Access Control

## Суть

Пользователь видит только свои заметки в списке, но endpoint `/note?id=...` не проверяет владельца заметки. Это классический IDOR: объект выбирается по предсказуемому идентификатору, а authorization check отсутствует.

## Как воспроизвести

1. Войдите как `alice / password123`.
2. Откройте:

```text
http://127.0.0.1:8090/note?id=3
```

3. Вы увидите заметку пользователя `bob`.

## Где проблема в коде

Функция `get_note_vulnerable()` в `vuln_notes/database.py` параметризованно
выбирает заметку только по `id`, но не связывает её с текущим пользователем:

```python
WHERE notes.id = ?
```

В запросе нет условия:

```sql
AND notes.owner_id = ?
```

## Impact

Любой авторизованный пользователь может читать приватные заметки других пользователей, перебирая `id`.

## Как исправить

Передавать `current_user.id` в запрос и проверять владельца:

```python
SELECT ...
FROM notes
WHERE notes.id = ? AND notes.owner_id = ?
```

Для админских ролей лучше делать отдельный явно описанный authorization path, а не оставлять неявный обход.
